# 개인 포트폴리오

빌드 도구 없이 순수 HTML/CSS/JS로 만든 정적 포트폴리오입니다.
GitHub Pages에 그대로 올려서 배포할 수 있습니다.

```
portfolio/
├── index.html        ← 내용(텍스트) 수정은 여기서
├── css/styles.css     ← 색상·폰트·레이아웃(디자인 토큰은 파일 맨 위 :root)
├── js/main.js          ← 내비게이션 토글, 프로젝트 필터, 키보드 상호작용
├── js/contact.js       ← 이메일 주소 (여기 한 곳만 수정)
├── .gitignore
└── README.md
```

## 1. 내 정보로 채우기

1. `index.html`을 열고 `<!-- EDIT: ... -->` 주석이 붙은 부분의 텍스트만 바꾸세요.
   구조(태그)는 그대로 두는 게 안전합니다.
   - 히어로의 **소개문구 3개**는 `intro-accordion` 안 각 `.accordion-item`의
     버튼 안 텍스트(제목)와 `.accordion-panel` 안 `<p>` 텍스트(상세 내용)를 바꾸면 됩니다.
     클릭하거나 `Enter`/`Space`를 누르면 펼쳐지고 접힙니다.
2. 이메일은 `js/contact.js` 맨 위 `CONTACT_CONFIG` 값만 바꾸세요.
   본문(`index.html`)에는 이메일이나 전화번호를 절대 평문으로 적지 마세요.
3. **비공개로 남기고 싶은 정보(전화번호, 상세 주소, 재직 중인 회사의 민감한 수치 등)는
   애초에 어떤 파일에도 적지 않는 것이 가장 확실한 방법**입니다. 지운 뒤 커밋해도
   Git 기록에는 남으므로, "안 적기"가 "적었다가 지우기"보다 항상 안전합니다.

## 2. 로컬에서 확인하기

브라우저에서 `index.html`을 더블클릭해서 열거나, 간단한 로컬 서버를 쓰세요.

```bash
# Python이 있다면
python3 -m http.server 8000
# 이후 http://localhost:8000 접속
```

## 3. GitHub Pages로 배포하기

1. GitHub에 새 저장소를 만들고 이 폴더 내용을 푸시합니다.
   ```bash
   git init
   git add .
   git commit -m "포트폴리오 초기 배포"
   git branch -M main
   git remote add origin <저장소 URL>
   git push -u origin main
   ```
2. 저장소 **Settings → Pages**로 이동합니다.
3. **Source**를 `Deploy from a branch`로, **Branch**를 `main` / `/(root)`로 지정 후 저장합니다.
4. 몇 분 후 `https://<사용자명>.github.io/<저장소명>/`에서 접속됩니다.

## 4. 커밋 전 "비밀값 0건" 체크리스트

이 사이트는 API 키·토큰·비밀번호가 전혀 필요 없는 구조입니다(순수 정적 사이트).
그래도 나중에 기능을 추가할 때를 대비해 다음을 습관화하세요.

- [ ] 커밋 전 `git diff`로 새로 추가된 내용을 눈으로 한 번 확인한다.
- [ ] `.env`, `*.key`, `*.pem`, `secrets.json` 같은 파일은 `.gitignore`에 이미 포함되어 있다(수정 금지).
- [ ] 만약 실수로 비밀값을 커밋했다면, 단순 삭제 커밋으로는 Git 기록에서 지워지지 않는다.
      `git filter-repo` 또는 GitHub의 [Removing sensitive data](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) 절차를 따르고,
      해당 값은 반드시 재발급(폐기)한다.
- [ ] 나중에 실제 문의 폼(EmailJS, Formspree 등)을 붙일 경우, "공개 키(public key)"라도
      코드에 그대로 두기보다 서비스 쪽 도메인 화이트리스트 설정으로 오남용을 막는다.

## 5. 배포 전 검증 체크리스트

### 두 해상도
- [ ] 1366×768에서 **스크롤하지 않은 상태**로 히어로의 소개문구 3개(아코디언 제목)가 모두 보인다.
- [ ] 1366×768, 1920×1080 모두 좌우 스크롤바가 생기지 않는다.
- [ ] 1920×1080에서 과도하게 빈 공간이 남지 않는다(콘텐츠가 뷰포트에 맞게 배치된다).
- [ ] 브라우저 개발자 도구(F12) → Device Toolbar 또는 창 크기 조절로 두 해상도를 직접 켜서 확인한다.

### 크로스 브라우저
- [ ] Chrome, Firefox, Safari(또는 Edge) 중 최소 2개 이상에서 레이아웃이 동일하게 보인다.
- [ ] 폰트가 로드되지 않는 상황(오프라인)에서도 대체 폰트로 깨지지 않는다.

### 키보드 상호작용
- [ ] `Tab` 키만으로 스킵 링크 → 상단 메뉴 → 소개문구 3개(아코디언) → 히어로 버튼 → 프로젝트 필터 → 프로젝트 카드 → 연락처 → 소셜 링크 → 맨 위로 버튼까지 순서대로, 빠짐없이 이동된다.
- [ ] 포커스가 이동할 때마다 파란 테두리(포커스 링)가 눈에 보인다.
- [ ] 소개문구 3개를 `Enter` 또는 `Space`로 펼치고 접을 수 있다(마우스 클릭과 동일하게 동작).
- [ ] 모바일 메뉴 버튼을 `Enter`/`Space`로 열고, `Esc`로 닫을 수 있다.
- [ ] 프로젝트 필터 버튼, 이메일 보기 버튼, 맨 위로 이동 버튼이 모두 키보드로 눌린다.

### 마우스 상호작용
- [ ] 프로젝트 카드에 마우스를 올리면 살짝 떠오르는 효과가 보인다.
- [ ] 필터 버튼 클릭 시 해당 카테고리 프로젝트만 남는다.
- [ ] "이메일 주소 보기" 클릭 시 주소가 표시되고, 다시 누르면 가려진다.

### 공개/비공개 분리
- [ ] `index.html`, `css/`, `js/` 어디에도 전화번호·상세 주소 등 공개하지 않기로 한 정보가 없다.
- [ ] `git log -p`로 과거 커밋까지 훑어봐도 비공개 정보나 비밀값이 없다(처음부터 안 적었으므로 확인만 하면 됨).
